# 공통헤더 지정 및 검증 후 기록

과거의 전체 NIC 저장 모드는 제거했습니다. admin/guest 모두 같은 기준으로 검사하며, **검사를 통과한 인터페이스 패킷만 해당 PCAP에 저장**합니다. guest의 CSV 변환 허용 목록은 이 기록 규칙과 별개입니다.

## 사용자가 지정하는 규칙

인터페이스 관리에서 ICD를 선택하고 **공통헤더 ID · Length / 메시지 매핑 설정**을 엽니다.

1. **현재 ICD**의 메시지 필드에서 ID·Length를 선택하거나, **별도 헤더 CSV/C++**를 가져와 헤더 메시지/구조체를 선택합니다. C++의 endian·pack·비트 순서는 직접 지정합니다. 필드 이름으로 역할을 추측하지 않습니다.
2. `header.ID`와 `header.Length` 역할을 각각 선택합니다. raw 정수/비트 필드이며 scale=1, bias=0이어야 합니다. signed 선언도 raw 비트 패턴으로 비교합니다.
3. 현재 ICD에서 선택하면 헤더 전체 크기를 입력합니다. 별도 구조체/헤더 CSV는 크기를 계산합니다.
4. **ICD에 공통헤더 포함** 여부를 지정합니다. 포함된 경우 선택한 헤더 필드들의 위치·타입·비트 폭·수치 비트 배치가 대상 ICD 메시지에 모두 존재해야 합니다. 이름의 경로 접두사는 달라도 되며, 1바이트의 BE/LE 표기는 동일하게 처리합니다.
5. ICD가 본문만이라면 별도 헤더를 선택합니다. 헤더 크기만큼 건너뛰고 본문 ICD를 적용합니다.
6. **Length가 헤더 포함 전체 UDP payload 크기**인지, 헤더를 제외한 본문 크기인지 지정합니다.
7. 메시지별 **기대 ID ↔ ICD 메시지명**을 등록합니다. ID는 10진수 또는 `0x` HEX를 받습니다. 최소 하나가 필요하며 중복 ID는 거절합니다. 사용하지 않은 메시지는 기록하지 않습니다.
8. **검증 후 적용 → 프로파일 저장**을 누릅니다. 체크섬은 현재 **없음** 모드입니다. 알고리즘을 추측하거나 필드를 체크섬으로 자동 간주하지 않습니다.

현재 완전한 **UDP 데이터그램**만 지원합니다. IPv4 조각, IPv6 확장/조각 재조립, TCP 스트림 재조립은 지원하지 않으므로 기록 대상에서 제외합니다. TCP 세그먼트 한 개를 완전한 메시지라고 임의로 취급하지 않습니다.

## 수신 처리 순서

- NIC에서 받은 프레임의 네트워크/UDP 경계를 검증합니다. 잘린 IP/UDP, 불일치한 UDP 길이, 비IP/비UDP는 저장하지 않습니다.
- 후보 인터페이스를 송신·수신 IP 및 방향으로 고릅니다. IP가 다르면 ICD 헤더를 읽지 않습니다.
- 선택한 헤더 ID를 읽고 메시지명을 결정합니다. 알 수 없는 ID는 제외합니다.
- 선언된 Length와 실제 UDP payload 길이가 지정한 기준대로 일치해야 합니다.
- 실제 payload 크기는 **정확한 ICD 크기 + 명시적인 헤더/본문 기준 오프셋**과 같아야 합니다. 부족한 바이트뿐 아니라 여분 바이트도 거절합니다.
- 정확히 하나의 인터페이스에만 맞아야 저장합니다. 여러 인터페이스에 동시에 맞으면 모호하므로 저장하지 않습니다.
- 검사 통과 후에도 PCAP에는 원본 프레임 바이트·타임스탬프·링크 타입을 그대로 저장합니다. 원본 네트워크 헤더를 잘라 저장하거나 패킷을 재작성하지 않습니다.

PCAP은 NIC→인터페이스별로 분리합니다. 첫 매칭은 `nic01.pcap`, 두 번째는 `nic01_profile02.pcap`처럼 저장하며 세션 메타데이터가 각 파일을 가리킵니다. 비활성 인터페이스는 저장하지 않습니다. 규칙이 없는 활성 인터페이스가 매핑돼 있으면 시작을 거절하고 설정을 요청합니다. 전체 저장으로 자동 복귀하지 않습니다.

PCAP→CSV도 동일한 ID·Length·정확한 ICD 크기 검사를 다시 적용해, 예전 전체 저장 파일에 다른 메시지가 섞여 있어도 선택 메시지만 해석합니다. 헤더를 별도로 뒀으면 본문 시작 오프셋을 적용합니다.

## ICD 기밀성

선택한 헤더 필드·ID 매핑·별도 헤더 원본/이름은 관리자 키로 암호화하고 서명된 설정에 저장합니다. guest에게는 기록에 필요한 최소 매칭 규칙만 별도 암호화 봉투로 전달하며 전체 ICD나 별도 헤더 원본은 전달하지 않습니다. CSV 변환 허용 여부와 관계없이 유효한 인터페이스 기록은 양 계정에서 동일합니다.

## 검증

임의 테스트 규격을 실제 사용자 프로토콜로 간주하지 않습니다. 테스트는 잘못된 IP/ID/Length/ICD 크기, 잘림, IPv4 조각, 모호한 인터페이스, 헤더 포함 여부 오류, 별도 헤더 암호화, guest의 제한 ICD 기록, 예전 혼합 PCAP의 선택적 CSV 변환을 확인합니다. 실제 헤더 위치와 ID는 UI에서 사용자가 지정합니다.

## 기대 ID 입력 없는 구조·길이 자동 매칭

새 공통헤더 설정은3번의 메시지별 기대 ID 입력을 없앴습니다. ID와 Length 필드를 선택하고 적용하면 현재 프로파일의 전체 ICD 메시지에서 선택한 헤더의 위치·타입·비트 폭·엔디언 구조와 호환되는 후보를 자동으로 구성합니다. NIC에 연결한 다른 프로파일들도 각자의 규칙으로 검사합니다. ID 숫자 값은 미리 제한하지 않습니다. Length와 실제 UDP payload 크기(선택한 헤더 포함 기준)를 확인한 뒤 정확한 ICD 크기로 메시지를 찾습니다.

같은 IP 방향·헤더 구조·전체 크기에 메시지 여러 개가 일치하면 ID 값 없이 구분할 수 없으므로 모호한 패킷으로 제외합니다. 첫 메시지를 임의 선택하거나 CSV 변환 화면의 선택 메시지로 강제 해석하지 않습니다. 구조 비호환 ICD는 후보에서 제외하고, 후보가 하나도 없으면 설정 적용을 거절합니다. 기존 IP·정확한 길이·미설정 거부와 guest 변환 권한은 유지됩니다.

이전 버전의 저장 규칙은 호환성을 위해 읽을 수 있습니다. 기존 프로파일은 공통헤더 설정에서 **헤더 포함 여부·크기 검사 후 적용**을 누르고 **암호화 저장**하면 기대 ID 없는 자동 구조 매칭 규칙으로 갱신됩니다. 새 설정에는 기대 ID 값을 저장하지 않으며 guest 최소 기록 규칙에도 자동 모드와 후보 크기를 함께 봉인합니다.
